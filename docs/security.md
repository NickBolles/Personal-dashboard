# Security

## Threat model (single household, self-hosted)

| Threat                                          | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Someone on the LAN claims a fresh instance      | One-time setup code printed in the server log (or `JARVIS_SETUP_CODE`) is required to claim.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Passcode guessing                               | scrypt hashes. Failures are stored in SQLite (`auth_failures`, survive restarts) and counted per client (5 free, then 30 s doubling to 15 min), per account (10 free, same backoff, whatever the IP) and globally (past 50 failures in 15 min, one attempt per 10 s). Login, setup code, invites, pairing codes and passcode change all use it. The client is the right-most `X-Forwarded-For` entry written by the trusted proxy (`JARVIS_TRUSTED_PROXY_HOPS`, default 1 = Traefik), IPv6 bucketed by /64. Guessing names that don't exist never locks a real account. Prefer `JARVIS_AUTH_MODE=proxy` behind Authelia/Authentik/oauth2-proxy for remote access. |
| CSRF                                            | Every mutation needs `x-jarvis-csrf: 1` (forces CORS preflight, which Jarvis never approves) **and** a same-origin `Origin`. Cookies are `HttpOnly; SameSite=Lax; Secure` in production.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Credential leakage to the browser               | Upstream credentials stay server-side, AES-256-GCM encrypted at rest (`JARVIS_SECRET_KEY` or `/data/secret.key`). Public integration views only say whether a secret is set. `npm run secrets:scan` checks client bundles and tracked files in CI.                                                                                                                                                                                                                                                                                                                                                                                                                |
| Credentials in Hermes tool output               | Hermes redacts previews; Jarvis scrubs again (`scrub()` in `integrations/hermes/normalize.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Lost or stolen phone                            | Each phone has its own device token (hashed on the server, Keystore-encrypted on the phone, excluded from backups). Sign it out from Settings → Phones; its next request is rejected. Pairing codes are single use, expire in 10 minutes, are throttled, and can only be minted by a browser session. Bearer requests never fall back to cookies and need no CSRF header (no ambient credentials).                                                                                                                                                                                                                                                                |
| Arbitrary session/run IDs                       | Session IDs validated by pattern; run IDs must belong to the user in the `runs` table before stop/approve/steer/stream.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Physical-world actions                          | HA allowlist (default: lock and close only; unlock/open are explicit opt-ins), explicit confirmation, live state token check, readback verification, audit log, disabled offline. Jarvis is never the only way to unlock a door.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Home data reaching the AI layer                 | Sent only when you ask (Ask Hermes / attached context), never by background syncs. The HA token never leaves the server. See below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Hermes-owned sources misreporting               | Structured requests (Skylight, Daily Compass) fail closed on prose, `{"error"}` or schema mismatch, stop on any approval request, and only count a completion that Hermes read back.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Duplicate side effects                          | Idempotency keys for Hermes runs (browser-generated, reused on retry) and Paperclip creates (deterministic from title + parent).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Resource exhaustion                             | Request bodies are counted while streaming and refused past 256 KB (`JARVIS_MAX_BODY_BYTES`; GitHub webhook 1 MB), so chunked uploads without `Content-Length` can't exhaust memory. Max concurrent SSE relays (`JARVIS_MAX_STREAMS`), per-source timeouts. The Next image optimizer is off (`images.unoptimized`), so `/_next/image` fetches and transforms nothing. CI fails on high/critical production advisories (`npm audit --omit=dev`).                                                                                                                                                                                                                   |
| A household member seeing more than they should | Capabilities per person (Settings → People), checked by every route (`api({ cap })`) and page, not only hidden in navigation. Hermes conversations are private to their owner unless shared read-only. Kids and the household tablet get no Hermes and no finance by default. Household PINs are 4+ digits, with the same lockout.                                                                                                                                                                                                                                                                                                                                |
| Finance data leaking                            | Never sent to Hermes or Claude. Notifications are opt-in and carry no amounts, account names or institutions. Hide-amounts toggle on web and phone. No account masks stored. The Monarch token is a server-side secret, never logged. Jarvis never moves money.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Camera images                                   | Proxied through Jarvis (HA token stays server-side), `Cache-Control: no-store, private`, never cached by the service worker or the phone, only for `home_assistant.cameras`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Push to internal URLs (SSRF)                    | Web Push endpoints must be `https` on a real push service (`fcm.googleapis.com`, `*.push.services.mozilla.com`, `web.push.apple.com`, `*.notify.windows.com`); anything else is refused, and stored ones are dropped before sending. You can only remove your own subscriptions.                                                                                                                                                                                                                                                                                                                                                                                  |
| Ownership drift                                 | The owner (who claimed Jarvis) is stored explicitly (`settings.owner_user_id`). They can't be demoted, disabled or removed, so passcode-only sign-in and Hermes-direct conversations never move to another admin.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Clickjacking / injection                        | CSP, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Caching sensitive data offline                  | The service worker never caches `/api/*`, and never caches Finance, Chat, Settings, People, login or join pages. Signing out (and any 401) drops the page cache; signing out also clears IndexedDB drafts and chat snapshots (≤10). "Clear local cache" in Settings wipes all of it.                                                                                                                                                                                                                                                                                                                                                                              |

## Planned: CSP without `'unsafe-inline'` scripts

`script-src` still allows `'unsafe-inline'` (Next's inline bootstrap scripts). The plan: build the CSP per request in `proxy.ts` with a nonce (`script-src 'self' 'nonce-…' 'strict-dynamic'`), which Next 16 applies to its own scripts; add `object-src 'none'` and `frame-src 'self'` (srcdoc widgets keep working); keep `'unsafe-inline'` only in `style-src`. This makes every page dynamically rendered, so it waits for an owner decision and a performance check.

## Proxy authentication is a deployment trust boundary

`JARVIS_AUTH_MODE=local` ignores proxy identity headers and uses passcodes. In `proxy` mode Jarvis trusts `JARVIS_AUTH_PROXY_HEADER` (default `remote-user`); the first accepted identity can become the admin. **Do not enable proxy mode until all of these are verified:**

- Traefik runs an actual authenticating middleware (Authelia/Authentik/oauth2-proxy) and includes it in `TRAEFIK_MIDDLEWARES`. The default `jarvis-headers` only emits security headers; it does not authenticate anyone.
- The trusted proxy strips client-supplied identity headers and sets the authenticated identity itself. Test an unauthenticated request containing a forged `remote-user`: it must not gain access.
- No app host port bypasses the proxy. Production Compose publishes none. Also restrict untrusted containers/hosts from reaching the app on its Docker networks: no host port alone is not full network isolation.
- Set `JARVIS_AUTH_PROXY_USERS` to the intended identities where practical. This allowlist is defense in depth, not a substitute for authenticating middleware.
- Any device-bearer bypass strips identity headers and still reaches Jarvis token validation; a forged bearer must return 401, never a proxy identity. Limit pairing exceptions to the documented pairing endpoint.

The explicit `docker-compose.local.yml` override binds only loopback and forces **local** auth. Do not use it for proxy-mode production. Live spoofed-header, passcode, device-token, and pairing checks remain deployment acceptance gates.

## Home Assistant and Hermes

Your decision (overriding the assessment's "never to the AI layer" rule): Home Assistant data **may** go to Hermes so you can ask questions about your home.

- Jarvis sends it only when you choose to: **Ask Hermes about my home** on the Home page, "Ask Hermes about this" on a card, or attaching a Home Assistant action or alert as context. Background work (structured syncs, the worker) never sends it.
- What gets sent is what Jarvis shows you: entity names and IDs, states, exception reasons, and health counts. The Home Assistant token never leaves the Jarvis server.
- Hermes can't **control** anything through Jarvis. Controls stay in Jarvis, behind the allowlist, a confirmation, and a readback.

## Claude direct (optional chat backend)

When you pick Claude for a conversation, the conversation text and any context you attached go to the Anthropic API instead of Hermes. The same rules apply as for Hermes: context is attached only when you ask, and finance is never attached. Claude can't call tools or control anything through Jarvis.

## Secret map

| Secret                                                                                                               | Where it lives                                                                          |
| -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Jarvis encryption key                                                                                                | `JARVIS_SECRET_KEY` env, else `/data/secret.key` (0600)                                 |
| Owner passcode                                                                                                       | scrypt hash in SQLite                                                                   |
| Phone device tokens                                                                                                  | sha256 in `devices` (raw token only on the phone, Keystore-encrypted)                   |
| Firebase service-account key (phone push)                                                                            | encrypted in `settings` (`fcm_config`), or `JARVIS_FCM_SERVICE_ACCOUNT(_FILE)`          |
| Hermes `API_SERVER_KEY`, HA token, Paperclip board key, Google client secret + refresh token, Skylight refresh token | encrypted in `integrations.secrets`, or env overrides (`HERMES_API_KEY`, `HA_TOKEN`, …) |
| Anthropic API key (Claude chat backend)                                                                              | encrypted in `settings`, or `ANTHROPIC_API_KEY` env; never returned to the browser      |
| Monarch session token                                                                                                | encrypted in `integrations.secrets`, or `MONARCH_TOKEN` env                             |
| Household member passcodes / PINs                                                                                    | scrypt hashes in SQLite                                                                 |
| VAPID private key                                                                                                    | encrypted in `settings` (or `JARVIS_VAPID_*` env)                                       |
| Session cookies                                                                                                      | sha256 of the token stored in `auth_sessions`                                           |

Backups (`scripts/backup.mjs`) contain the encrypted DB **and** the key file: store them privately.

## Audit

`audit_log` records actor, action, source record, result (`ok`/`error`/`rejected`/`pending`) and correlation ID for: Hermes starts/stops/approvals/steers/renames/forks, HA controls and light switches, todo mutations, finance writes (before/after), people and capability changes, Paperclip track/unlink, integration changes, passcode change. Values that look like credentials are redacted before storage. View it at Settings → Activity log.

## Phase 5: AI jobs, capture tokens, attachments

- **Capture tokens** (`jcap_…`): sha256 at rest, shown once, label + prefix hint only afterwards; accepted **only** by `POST /api/capture` and `GET /api/capture/:id` (own captures). `resolveUser()` only knows `jdv_` device tokens, so a `jcap_` bearer gets 401 everywhere else (tested on home, work items, Hermes sessions, finance). Expiry (default 1 year), revoke (next request), per-token rate limits (30/h, 300/day → 429 + retry-after), failed-auth throttle (`ip:capture:<ip>`, `global:capture`), audit `capture_token.create|revoke` without the value. Managed from a browser session only.
- **`/api/capture`**: explicit CSRF on the cookie path; body streamed with a 25 MB cap before multipart parsing; ≤ 4 files ≤ 10 MB; magic-byte sniffing (PNG/JPEG/WebP/GIF/plain text; SVG/HTML refused, declared type must match → 415); files written 0600 under `${JARVIS_DATA_DIR}/captures/<user>/<random id>` (never user-controlled, never under `public/`); served owner-only with `nosniff`, `no-store, private` and a sandbox CSP. Jarvis never fetches captured URLs (no SSRF surface).
- **Finance guard** (`server/ai/rules.ts#financeGuard`), checked at enqueue and again at execution: Finance areas are always excluded (pure rule, not just UI); finance/credential heuristics skip AI. A unit test walks the static import graph of `server/ai/**` and asserts no finance module is reachable.
- **Prompt injection posture**: untrusted text in `<data>` blocks, read-only instructions, hidden jobs stop on any approval request, outputs zod-validated, source URLs restricted to public http(s), Markdown rendered without raw HTML or images (`components/work/ai/SafeMarkdown.tsx`).
- **No model text in job rows**: `ai_jobs` keeps controlled error codes/messages only; the validated report is the only stored model output.
- **Budget** bounds total spend (and a leaked capture token, which can also be `triage_only`/`off`).
- Rollback: Settings → AI → Enabled off stops the runner (queued jobs stay); removing `work.ai` hides everything; capture keeps working deterministically.
