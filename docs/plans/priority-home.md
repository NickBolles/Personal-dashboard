# Plan: prioritized Home, feedback and mobile polish

Branch `feat/priority-home`. Problem: once sources are connected, Home lists
everything in Now / Later today / Upcoming. Goal: a small attention budget,
honest totals, grounded suggestions, and feedback that actually changes the
ranking. All of it on the server, so web and phone agree.

## Ranking (pure, `server/ranking/attention.ts`)

1. Scope → dedupe → apply the person's snoozes/pins → count. Totals are computed
   after filtering, before paging.
2. Tier each open action, first match wins:
   `critical` → `awaiting_user` → `pinned` → `compass` (matches today's Daily
   Compass focus) → `overdue_recent` (due today or yesterday, local tz) →
   `due_soon` → `checkin_window` → `today` → `overdue_stale` → `upcoming`
   (dated, within 14 days, or deferred) → `someday` (undated or further out).
3. Within a tier: category weight (feedback) → due → updatedAt → id.
4. Buckets: Now ≤ 3 and Today ≤ 5, taken from `critical`…`today`. Upcoming
   preview ≤ 3. Everything else is the **backlog**, counted and pageable
   (`GET /api/home/items`). `critical` is never budgeted away, snoozed or
   demoted: extra critical items go over the Now budget.
5. Each action carries `why: string[]` (plain reasons, e.g. "Overdue 3 days",
   "Matches Daily Compass focus “taxes”", "You asked for fewer Todos").

Compass: the Hermes status answer gets an optional, bounded `priorities`
(≤ 5 × 120 chars). If it's missing, `attention.compass.state` says so. Nothing
is invented. Only people with `daily_compass.use` get it (existing scoping).

## Feedback and tuning (per person, `server/home-tuning.ts`)

- `home_feedback`: immutable rows (verdict, optional correction ≤ 500 chars,
  compact provenance: version, fingerprint, reasons, sources), unique per
  `(user, idempotencyKey)`.
- `home_category_prefs`: weight −2…+1 per category (`source:todos`,
  `assist:seasonal`…). "Less like this" means −1, "Helpful" means +1 (capped).
  At −2, the category's non-urgent items leave Now/Today (still counted in the
  backlog), and its suggestion cards stop.
- "Not now" reuses `action_prefs.hiddenUntil` (assist cards use `assist:*` ids).
- "Not helpful" mutes that card fingerprint for 14 days. "Wrong assumption"
  mutes it until the underlying data changes. On an action it keeps the action
  out of Now.
- `home_milestones`: dates the person typed in (birthday, anniversary), private
  to them. They're the only source of "plan ahead" besides visible calendar events.
- Settings → Home priorities: weights, snoozes, milestones, recent feedback,
  per-item delete, reset all. "Tune with Hermes" opens a chat with a bounded
  summary attached. Hermes can only suggest; the person changes settings.

## Suggestion cards (deterministic, ≤ 2 shown)

- Overdue triage: from real overdue counts (≥ 3). "Review & reschedule" opens a
  dialog. The person ticks tasks and picks a date, then confirms. Each task goes
  through the existing `POST /api/actions` snooze path (readback). "Help me
  triage" opens chat with a draft plus bounded context. Nothing is sent until
  they press send.
- Plan ahead: milestones within their lead time (default 60 days), plus visible
  calendar events titled birthday/anniversary.
- Seasonal (Christmas gifts, from Nov 1): labelled as a seasonal idea, not a
  calendar event.
- Cards are versioned, fingerprinted and snoozable. They never include finance
  or other people's private data.

## UI

- Web: compact header with attention summary and Compass focus; accent-bar
  cards; "Why this?" disclosure with feedback; suggestion cards; Today / Upcoming
  with "See all N"; backlog row → `/home/all`; skeleton; pressed states; done
  animation; `prefers-reduced-motion` respected. No haptics on the web (no
  existing safe abstraction).
- Android: additive models (`why`, `attention`, `assists`), counts in headers,
  suggestion cards with Ask/Not now, why line on cards. These changes are
  unbuilt in this branch; the parent runs Gradle and Roborazzi.

## Tests

Unit: budgets, safety over budget, stale/missing Compass, focus boost, category
weights, snooze expiry, timezone boundaries, dedupe, paging totals. API:
auth/CSRF, ownership, idempotency, size limits, reset. E2E: Home budget and
overflow at 320/412/1280, triage dialog, tuning page. Visual baselines are
regenerated by the canonical CI workflow (none are committed here).
